# Run guide

Everything runs on one laptop: Postgres in Docker, the API on port 4000, the website on 3000, and the app in Expo Go. Payments and OTP texts are simulated until you add keys.

## 1. One-time setup

```bash
bun install
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env.local
bun run db:up        # Postgres 16 with the hostels and hostels_test databases
bun run db:reset     # migrate and load the Hyderabad demo data
```

## 2. Start it

In three terminals:

```bash
bun run dev:api      # http://localhost:4000  (GET / shows database and stub status)
bun run dev:web      # http://localhost:3000
bun run dev:mobile   # scan the QR code with Expo Go (SDK 58)
```

On a phone, the app must reach your laptop. Use its LAN address:

```bash
EXPO_PUBLIC_API_URL=http://192.168.1.10:4000 EXPO_PUBLIC_WEB_URL=http://192.168.1.10:3000 bun run dev:mobile
```

and add `http://192.168.1.10:8081` to `CORS_ORIGINS` in `apps/api/.env` if you also use the app's web preview.

## 3. Try each persona

All logins use OTP `123456` in dev mode.

| Who | Phone | Where | Try this |
|---|---|---|---|
| Seeker | any new number | website `/hostels`, or the app's Explore tab | Filter by area, budget and "Verified, no advance"; open a hostel; read verified reviews and the issue record; request a visit or subscribe and pay (simulated) |
| Resident | `9000000003` | website `/account` and `/stay`, or the app's My Stay tab | Skip a meal, see bills, report an issue, post on the community board, write a review |
| Owner | `9000000002` | website `/owner` | Edit a listing, upload photos, update free beds, add a resident, record rent, answer an issue, reply to a review, edit the menu, see the kitchen headcount, change plan |
| New owner | any new number, tick "I own or run a hostel" | website `/for-owners` | List a hostel from scratch, submit it, then apply for Partner once it is live |
| Admin | `9000000001` | website `/admin` | Approve listings, verify partners, set fees, generate payouts, moderate flagged reviews, run the background jobs |

## 4. Checks

```bash
bun run typecheck
bun run lint
bun run test                     # API tests use the hostels_test database
bun --filter @hostels/web e2e    # Playwright golden path against the dev database
```

The golden path starts the API and website if they are not running. It needs Chromium: run `bunx playwright install chromium` once. It creates a new owner, hostel and tenant on every run, so it can be repeated without a reset.

## 5. Build the Android app

Expo Go is enough for day-to-day work. To get an installable APK (testers) or an AAB (Play Store), build the native app. All commands run from `apps/mobile`.

**Per-build settings.** `app.json` holds the shared config (icon, adaptive icon, splash, `versionCode`, the `hostels://` link scheme). `app.config.ts` layers on what changes per build, read from env vars:

| Variable | What it does |
|---|---|
| `APP_VARIANT` | `development` (default), `preview` or `production`. Non-production builds are named "Hostels (preview)" etc. |
| `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_WEB_URL` | The API and website the app talks to. Baked into the bundle at build time. |
| `GOOGLE_MAPS_ANDROID_API_KEY` | Google Maps key for the hostel map. Without it the map screen does not work on Android builds. |

Plain `http://` URLs (an API on your LAN) are allowed only in development and preview builds; production builds allow HTTPS only.

**Icons and splash.** The PNGs in `assets/` are drawn by `scripts/generate-assets.py` in the brand colours. Change the script and run `bun run assets` (needs Python with Pillow) to redraw them.

### Local build with Gradle

Needs JDK 17 or newer and the Android SDK (install Android Studio, or the command-line tools with `sdkmanager "platform-tools" "platforms;android-37" "build-tools;37.0.0" "ndk;27.1.12297006"`; Gradle fetches anything else it needs), with `ANDROID_HOME` set.

```bash
cd apps/mobile
EXPO_PUBLIC_API_URL=http://192.168.1.10:4000 EXPO_PUBLIC_WEB_URL=http://192.168.1.10:3000 bun run build:android:debug
# APK: android/app/build/outputs/apk/debug/app-debug.apk
adb install android/app/build/outputs/apk/debug/app-debug.apk
```

A debug APK loads its JavaScript from the Metro server, so keep `bun run dev:mobile` running. For a standalone APK that bundles its JavaScript:

```bash
EXPO_PUBLIC_API_URL=https://api.example.com EXPO_PUBLIC_WEB_URL=https://example.com bun run build:android:release
# APK: android/app/build/outputs/apk/release/app-release.apk (signed with the debug key, fine for testing only)
```

`android/` is generated by `expo prebuild --clean` on every build and is gitignored: change `app.json`/`app.config.ts`, never the generated files. To check the JavaScript bundle without the SDK, run `bun run export:android`.

### Cloud build with EAS

`eas.json` has three profiles. Set the real URLs in each profile's `env` first (the preview and production hosts are placeholders).

| Profile | Output | Use |
|---|---|---|
| `development` | debug APK, LAN `http://` API | Your own phone, with Metro running |
| `preview` | release APK | Share with testers (install link from EAS) |
| `production` | AAB, `versionCode` bumped by EAS | Upload to Google Play |

```bash
bunx eas-cli login
bunx eas-cli init                              # once: links the project to your Expo account
bunx eas-cli secret:create --name GOOGLE_MAPS_ANDROID_API_KEY --value <key>   # or set it under the project's environment variables
bun run eas:preview                            # APK
bun run eas:production                         # AAB
bunx eas-cli submit --platform android --profile production   # Play Console, internal track
```

EAS stores the Play signing key for you on the first production build. With local builds, raise `android.versionCode` in `app.json` for every Play upload.

## 6. Going live

Before real users, set these in `apps/api/.env` (the API refuses stub OTP and stub payments when `NODE_ENV=production`):

- `MSG91_AUTH_KEY` and `MSG91_TEMPLATE_ID` for OTP texts
- `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET` and `RAZORPAY_WEBHOOK_SECRET`, with the webhook pointed at `https://<api-host>/webhooks/razorpay`
- `OTP_PEPPER` to a long random value, `ADMIN_PHONES` to your team's numbers
- `API_PUBLIC_URL`, `WEB_URL` and `CORS_ORIGINS` to the real hostnames, all on HTTPS

See [security-review.md](security-review.md) for what was checked and what is still open.
